# Dynamic Reference Mapping (offline specification)

## Objective and coordinate contract

Opt-in `vision.reference_mode: auto` determines the current table-plane geometry from calibrated camera images. ID 2 is the origin; its printed right and top edges define +X and +Y, and the tag normal defines +Z. Units are metres. All reference markers must lie flat on the same plane and have the configured 0.08 m **black marker** side length. Their centres may form any nondegenerate arrangement and may rotate within the plane. The origin and axes move if ID 2 moves or rotates; no absolute table coordinate can be recovered without another surveyed landmark.

The default `fixed` mode retains the existing surveyed coordinates, board geometry, commissioning file and orchestration behaviour. Auto mode never reads `tags.reference.positions` to compute geometry and never writes calibration, commissioning, or site files. It does not load a fixed commissioning file. A fresh accepted image batch is required after startup and after any mapping failure.

## Algorithm and quality gate

Solve both IPPE square poses of ID 2 with the calibrated intrinsics. Each viable pose seeds a joint robust Levenberg–Marquardt fit of camera rotation/translation and independent X/Y/yaw for every other visible reference marker. All four marker corners are projected with the calibrated distortion model; each marker remains a fixed 0.08 m square on Z=0. No measured separation or rectangular arrangement is used. A 1.5 px Huber loss limits the influence of individual corner errors. The implementation uses NumPy and OpenCV only. OpenCV documents the [IPPE square corner order and two solutions](https://docs.opencv.org/5.0/main_modules/d_projection.html) and [projectPoints with distortion and pixel residuals](https://docs.opencv.org/5.0/main_modules/d_projection.html).

Require ID 2 and two other reference markers in each accepted frame. Keep the 0.012 m square-consistency limit, measured by back-projecting the observed corners through the fitted camera; this is an **in-fit diagnostic**, not independent position accuracy. Reject any observed reference with a corner residual over 5 px by rejecting the entire frame, naming its ID. Also require camera height ≥0.15 m, positive corner depth, rays sufficiently below the horizon, projected marker edges ≥12 px, reference-centre hull area ≥0.005 m², and a clearly preferred IPPE pose. These gates prevent a low-residual but physically invalid fit from being used. Huber weighting does not silently remove a tag; all detected reference tags are retained in an accepted frame.

For a batch, require ≥60% reliable frames and a reliable latest frame. Median reference positions are retained only for markers in the latest frame that appear in ≥60% of reliable frames. Reject a batch if any retained reference drifts over 0.025 m from its median. With ≥3 reliable frames, the first approximately 70% form a training set; the remaining frames are held out and must agree with the training median within 0.025 m. This holdout tests repeatability across frames, not surveyed accuracy. A moved camera is allowed because each frame gets its own pose. A reference moved *during* the batch is rejected; start a fresh batch after moving tags. Never reuse a previous camera pose to make an invalid new map pass.

At low view angles, a short far-marker edge carries less information about its range. The real ID 0 edge is only about 23 px in its compressed direction, so a small corner or coplanarity error may shift the inferred table coordinate by centimetres. The minimum-edge, hull-area, pose-ambiguity, residual, and temporal gates limit this risk but do not establish absolute accuracy. Printed black-square size, flatness, focus, and calibration at the actual resolution remain physical requirements.

Use the accepted camera pose and existing node-tag PnP path to locate IDs 21/22. A pixel on the table is the forward intersection of its calibrated ray with Z=0. Auto mode's YOLO output is the **table contact-point estimate** `(X,Y,0)`; a single image cannot recover the height of an arbitrary flame. The position of a separate vertical board is also unobservable from reference tags alone, so auto mode does not claim wall coordinates. Limit extrapolation outside the convex hull of visible references.

## Commands, structure and style

- From `pi/`: `uv run pytest tests/test_dynamic_mapping.py`, then `uv run pytest tests`; `uv run ruff check src/nt532/vision scripts/dynamic_map.py tests/test_dynamic_mapping.py`.
- Run the optional 24-frame real-image regression with `NT532_LOW_ANGLE_DATASET` pointing to the external dataset directory. Keep the images outside Git.
- CLI: `uv run python scripts/dynamic_map.py --image-dir PATH --intrinsics PATH_TO_CAMERA_YAML --json map.json` reads all JPG/PNG frames. The old `--image` and `--source` commands still work. Node tags 21/22 are optional. JSON reports detected/used/rejected tags, per-frame pixel and fitted-corner quality, both anchor IPPE candidates, camera pose, references, stability, holdout drift, and a rejection reason when applicable. `anchor_reprojection_px` is the ID 2 IPPE error; `joint_reprojection_px` is the fitted all-marker RMS.
- Core: `pi/src/nt532/vision/dynamic_mapping.py`; integration: `system.py`; headless Pi CLI: `pi/scripts/dynamic_map.py`; synthetic tests: `pi/tests/test_dynamic_mapping.py`.
- Keep existing NumPy arrays, `Camera`/`TagPose` types, snake_case names and explicit `ValueError` for bad geometry. Example: `mapping = estimate_reference_map(corners, intrinsics, size=0.08)`.

## Verification and boundaries

Synthetic ground truth is generated independently from the estimator. Test 60×40 cm, 80×50 cm and asymmetric layouts, changed camera pose, moved reference, missing anchor, table pixel, node poses, noisy/ambiguous observations, and fixed-mode regression. Aim for ≤2 cm position error on accepted scenes; report measured errors and rejected cases. Real camera tests must validate printed marker size, intrinsics at actual focus/resolution, motion blur, partial occlusion, lens distortion and millimetre-scale height differences.

The external `low-angle-fail` dataset contains 24 post-move frames, three of which are byte-identical. The previous anchor-only estimator rejected 24/24 frames: square error 0.0128–0.0182 m despite ID 2 IPPE reprojection 0.625–0.761 px. ID 0/2/3 were detected in 24/24 and ID 1 in 21/24. With the joint fit, 24/24 frames pass: observed-square error 0.0030–0.0059 m, all-marker RMS 1.63–1.93 px, maximum reference-centre drift 0.00228 m, and held-out drift 0.00083 m. No reference tag was removed. The fitted ID 0 centre is about (0.0186, 0.4957) m in the ID 2 frame. These images have no independently surveyed coordinates, so this result cannot support a ≤2 cm real-camera accuracy claim. The old `before-pass.json` is a prior output, not a before-move image sequence.
